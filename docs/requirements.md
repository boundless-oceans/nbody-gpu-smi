## 1. 项目概述

### 1.1 一句话定位

**基于 CUDA 的实时 N 体引力模拟器**：用户可通过界面设置粒子数量（N）、选择不同的质量分布模式与预设天体场景，实时观察不同质量天体在万有引力作用下运动的直观效果。

### 1.2 项目目标

1. **练手主目标**：以 NVIDIA CUDA Samples 官方 nbody 为蓝本，系统学习并实践 CUDA 性能优化核心技术（共享内存 tiling、双缓冲、内存合并、常量内存、归约）。
2. **成品目标**：在 NVIDIA 版基础上做"交互升级"，让用户通过界面调整参数并获得直观视觉反馈，达到"可玩的模拟器"水准。
3. **技术探索**：打通 CUDA ↔ OpenGL 的零拷贝渲染链路（CUDA-GL Interop），为后续自研 GPU 应用积累经验。

### 1.3 项目背景

- 作者已具备 CUDA 基础语法知识（kernel 编写、线程层级、内存管理），在 Ubuntu 上安装了 CUDA 11.8 与 RTX 4060 Laptop 显卡（计算能力 8.9）。
- 已成功编译运行 NVIDIA CUDA Samples 的 nbody 官方示例（benchmark: 24576 体 5 次迭代 11.281ms，2677 亿次引力交互/秒）。
- 本项目以该官方示例为基础进行功能扩展，而非从零编写物理内核。

## 2. 现有基础分析（NVIDIA 版技术栈拆解）

> 本项目建立在对 NVIDIA 官方示例的充分理解之上，下表为已确认的现有资产。

### 2.1 可直接复用的资产

| 资产 | 所在文件 | 价值 |
|---|---|---|
| CUDA 物理内核（共享内存 tiling + 双缓冲 + `__restrict__` + cooperative groups 同步 + float/double 模板） | `bodysystemcuda.cu`（282 行） | 官方最优实现，零改动复用 |
| CUDA-GL Interop 零拷贝管线（`cudaGraphicsGLRegisterBuffer` + Map/Unmap + PBO） | `nbody.cpp` + `render_particles.cpp` | GPU↔GPU 数据通路，无需重写 |
| CPU 对照实现（OpenMP 并行） | `bodysystemcpu_impl.h` | 用于正确性验证（`-compare`） |
| Tipsy 宇宙模型加载器 | `tipsy.h` | 可加载真实宇宙模拟数据 |
| 高斯点精灵渲染（splat 纹理 + 视距缩放 shader） | `render_particles.cpp` | 粒子渲染基础 |

### 2.2 现有实现的局限（本项目要解决的）

| 局限 | 说明 |
|---|---|
| 交互简陋 | 仅键盘回调（空格暂停、P 切换显示模式、鼠标拖动），无参数控制面板 |
| N 无法运行中调整 | 启动时固定，改 N 需重启程序 |
| 质量无差异化 | 所有粒子质量相同参与物理，渲染大小/颜色统一 |
| 无场景预设 | 只有随机分布，无双星/星系盘/太阳系等经典开局 |
| 无状态反馈 | 不显示 FPS、总能量等运行指标 |
| 老式渲染 | GLSL 1.20 固定管线，点精灵效果单一 |

## 8. 关键技术点设计

### 8.1 质量 → 渲染映射

```
┌────────────────────────────────────────┐
│ 质量 m（float4.w）                      │
│    ↓ log 归一化（质量跨度可达 1000x）    │
│ 归一化质量 q ∈ [0,1]                    │
│    ↓                                    │
│ 颜色：HSL 从蓝(0) → 红(1) 插值          │
│    ↓                                    │
│ 半径：pointSize = base + q * scale      │
└────────────────────────────────────────┘
```

- 避免线性映射（大质量会吞掉动态范围），采用 `log` 压缩
- 颜色映射产生"大红=重，小蓝=轻"的直观效果

### 8.2 总能量计算（GPU 归约）

```
每帧（或每 k 帧）：
    1. 动能核：Σ ½·m·|v|²          ← 直接并行归约
    2. 势能核：对所有粒子对 Σ -G·mᵢ·mⱼ/|r|  ← 复用 tiling 循环
    3. block 内共享内存归约 → 原子加到全局 → GPU 归约 kernel
    4. 结果拷回 CPU（一小块数据，开销可忽略）
    5. UI 画曲线，验证能量守恒
```

### 8.3 场景预设物理要点

项目以**纯物理 N 体模拟为核心定位**，预设场景分两级：核心物理场景（默认、聚焦 CUDA 物理本身）与宇宙主题彩蛋场景（扩展、视觉卖点）。

**核心物理场景（默认）**

| 场景 | 生成要点 | 预期视觉 |
|---|---|---|
| 随机粒子云 | 三维空间均匀随机位置，整体质心静止 | 引力聚散、结构演化 |
| 双粒子互绕 | 两个等/不等质量粒子，满足轨道速度 | 经典近距离互绕 |
| 格点扰动 | 规则格点分布 + 微小随机速度扰动 | 规则结构坍缩成簇 |

**扩展宇宙场景（彩蛋）**

| 场景 | 生成要点 | 预期视觉 |
|---|---|---|
| 双星系统 | 两颗等/不等质量体，伯努利轨道速度 | 椭圆形互绕轨道 |
| 旋转星系盘 | 盘状分布 + 开普勒速度场（内快外慢） | 旋臂结构自然演化 |
| 太阳系 | 行星轨道半径 + 开普勒第三定律初速度 | 行星稳定公转 |

### 8.4 N 动态调整策略

- N 变化时：释放旧 buffer → 重新分配 `numBodies × 4 × sizeof(float)`（位置 PBO + 速度 buffer + 颜色 buffer）→ 调用 SceneGenerator 重新生成
- GPU 内存上限检查：`cudaMemGetInfo` 预检，超限提示而非崩溃
- N 上限 100,000 的内存公式：`(4+4+4)×4B × 100k ≈ 4.8MB`，远低于显存，制约在 O(N²) 算力而非内存

### 9.1 实现顺序（依赖驱动的开发次序）

> 本项目的技术栈为 **ImGui + GLFW + 现代 OpenGL + CUDA**，从 NVIDIA 版（GLUT + 固定管线）迁移需按依赖次序逐层搭建。每一步都应有可运行的验证点，避免"最后一步才能跑"。

| 步骤 | 内容 | 依赖 | 验证点 | 对应里程碑 |
|---|---|---|---|---|
| **S1 工程骨架** | CMakeLists（CUDA + OpenGL + GLFW + FetchContent 拉 ImGui）+ GLFW 窗口 + ImGui 空面板 | 无 | 窗口弹出、ImGui 面板可拖拽 | M4 前置 |
| **S2 物理内核移植** | 从 NVIDIA 版迁移 `bodysystemcuda.cu`（tiling + 双缓冲 + 常量内存），去掉 GLUT 依赖 | S1 | `-benchmark` 模式跑通，性能与官方版一致（2677 亿次交互/秒） | M1 前置 |
| **S3 CUDA-GL Interop** | `cudaGraphicsGLRegisterBuffer` 注册 PBO，Map/Unmap 打通 GPU↔GL | S1+S2 | 粒子位置在 CUDA 计算后能被 GL 读取（可先画静态点验证） | M1 前置 |
| **S4 粒子渲染** | 现代 OpenGL（VAO/VBO + 自写 GLSL 330 shader）渲染粒子点精灵 | S3 | 看到粒子动态运动（纯白色） | M1 前置 |
| **S5 质量映射** | 质量 → log 归一化 → 蓝红插值颜色 + 半径缩放（F-03） | S4 | 大红=重、小蓝=轻，视觉对比明显 | M1 |
| **S6 场景与质量模式** | SceneGenerator：核心场景（随机云/双粒子/格点）+ 宇宙彩蛋（双星/星系盘/太阳系）+ 三种质量模式（F-02/F-04） | S5 | 点击按钮即切换场景与质量分布 | M2 |
| **S7 交互控制** | ImGui 控件：N 滑条（动态重分配）、开始/暂停/单步/重置、FPS 显示（F-01/F-05/F-06） | S6 | 运行中改 N 立即生效；暂停/单步正确 | M2 |
| **S8 能量曲线** | GPU 归约算动能+势能 → ImPlot 曲线（F-07） | S7 | 曲线平稳，漂移 <0.1%/千步 | M3 |
| **S9 可视化增强** | 按速度染色、轨迹尾迹、步长滑条、质量随机幅度（F-08/F-09/F-10） | S8 | 各开关独立生效 | M4 |
| **S10 性能回归** | 实测 N=10k/50k/100k 帧率，对照需求阈值；`nsight-compute` 分析内核瓶颈 | S9 | N≤50k ≥60FPS；N≤100k ≥25FPS | M5 |
| **S11 扩展彩蛋（可选）** | 碰撞合并、Tipsy 加载、参数导出、CPU 对比（F-11~F-14） | S10 | 各功能验收通过 | 后期 |

**开发原则**：
1. **每步可运行**：S1~S10 每一步结束都有可执行的产物，不以"最后一步"为目标
2. **物理内核优先保真**：S2 移植后先跑 benchmark 与官方版对比，确认零性能回退，再进入渲染
3. **先核心后彩蛋**：核心物理场景（随机云/双粒子/格点）先实现，宇宙主题全部放入彩蛋阶段
4. **ImGui 先空壳**：S1 先让 ImGui 面板能显示，控件逻辑 S6/S7 再加，避免过早耦合
5. **验证驱动**：每个里程碑对应文档第 11 章验收标准中的对应项

## 10. 风险与应对

| 风险 | 等级 | 应对措施 |
|---|---|---|
| 现代 OpenGL 管线（3.3+）在新环境兼容性 | 低 | 当前环境支持 OpenGL 4.6；CUDA-GL interop 已实测通过 |
| O(N²) 算法上限 | 中 | 滑条上限 100k + 帧率降级提示；进阶可加 Barnes-Hut |
| 大质量近距离数值爆炸 | 中 | 保留 `softeningSquared` + 步长上限提示 |
| Wayland 下 CUDA-GL interop 兼容性 | 低 | 当前 X11 无碍；异常时切换 Xorg |
| GPU 驱动与 CUDA 版本不匹配 | 低 | 已实测通过（RTX 4060 + CUDA 11.8） |
| 双缓冲/显存管理 Bug | 低 | 保留 NVIDIA `checkCudaErrors` 封装 + N 变化时内存预检 |
